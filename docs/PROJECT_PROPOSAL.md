## 一、 项目立项背景与核心愿景

### 1.1 行业现状与瓶颈
当前以大语言模型（LLM）为底座的智能体系统大多受制于**“静态工作流”**或**“一次性 Prompt 编排”**：
- **能力边界出厂即固化**：开发者预先注册了什么工具，Agent 就只能调用什么工具；遇到从未见过的复杂任务时，缺乏自我拓展手段。
- **状态拓扑僵化**：即便使用 LangGraph 等先进框架，大部分系统的图结构（DAG / 状态机）在编译阶段就已经完全固定，无法根据任务难度的动态变化自适应增减通道与分支。
- **决策成本高昂且脆弱**：简单条件分支和工具挑选均依赖通用大模型反复生成 JSON，推理开销大、响应延迟高，且极易出现指令漂移。

### 1.2 项目愿景
本项目致力于突破上述局限，探索**递归自改进（Recursive Self-Improvement, RSI）**在通用 Agent 领域的工程化实现路径：

> **“构建一个具备‘运行时能力边界自拓展’能力的通用 Agent 内核。在任务推进与环境交互中，Agent 能够自主感知能力短板，自主生成并热加载所需插件，动态改写状态图拓扑，并通过专属轻量决策模型实现持续的效果验证与纠偏闭环。”**

**设计原则——“内核高度收敛，场景极低成本迁移”**：  
底层不绑定任何单一行业逻辑。应用层既可以是自主扩展教学手法的 AI 智能助教，也可以是自主探索 API 的运维或科研助理——更换场景只需替换插件包，甚至直接让 Agent 在交互中自行改造自身 Harness。

## 二、 核心技术路线与创新点

整体架构呈现为“动态图骨架 + 插件生态血肉 + 轻量决策大脑”的三位一体系统：

```
                 ┌────────────────────────────────────────────────────────┐
                 │                System 1 高速决策与自校验               │
                 │   (Jev-like 分类/打分模型: 极速路由 / 风险控制 / 结果评估) │
                 └───────────────▲────────────────────────▲───────────────┘
                                 │ 状态评估 / 选路决策    │ 改进效果闭环校验
┌────────────────────────────────┼────────────────────────┼──────────────────────────────┐
│  【骨架】LangGraph 动态状态图   │                        │  【血肉】Cordis 插件热插拔   │
│                                │                        │                              │
│  • 运行时动态加边 / 增减通道   │                        │  • 一切皆插件（Lifecycle）   │
│  • 节点路由与拓扑自我演进      │                        │  • Agent 自写 Tool 并安全挂载│
│  • 状态机上下文分级压缩        │                        │  • 依赖自动解析与隔离运行    │
└────────────────────────────────┴────────────────────────┴──────────────────────────────┘
                                 │
                   ┌─────────────┴─────────────┐
                   │  通用解耦层 (FastAPI/SSE) │
                   └─────────────┬─────────────┘
                                 ▼
      【应用落地示例】：自演进 AI 助教 / 复杂科研助理 / 自动化研发运维
```

### 2.1 骨架：LangGraph 动态状态图与运行时拓扑演进
- **长程状态机编排**：以 LangGraph 的状态图为底层骨架，维持 `compact → agent ⇄ tools` 的精简核心循环，内建自动状态分级压缩（Compaction）机制。
- **运行时图拓扑重构（Dynamic Graph Mutation）**：
  突破传统静态图限制，设计图演进中间件，允许 Agent 在遇到分支阻滞或高并发子任务时，**在运行时动态新增状态通道（Channels）、动态注入节点（Nodes）并重写边（Edges）**，完成自适应拓扑扩展。

### 2.2 血肉：Cordis 思想与插件热插拔机制
- **一切皆插件（Everything-is-a-Plugin）**：参考 Cordis 框架理念，彻底打破装配根的硬编码。工具、技能、安全审批、存储层均定义为独立生命周期的插件模块。
- **Agent 自写自挂载（Self-Authoring Tools）**：
  当外部环境超出内置工具能力集时，Agent 触发“自我扩充子流程”，自主编写 Python 工具代码、在沙箱中完成单元自测，并通过容器 API 实现热加载（Hot-Plug），无需停机即可完成能力扩充。

### 2.3 大脑皮层：Jev 类 System 1 决策模型与闭环校验
- **结构化快思考模型代替主模型**：
  引入类似 Jev（TypeSafe AI）的非生成式专用决策模型。此类模型不生成文本，直接对状态输出带概率与置信度的 `Choice / Score / Boolean`，用于做工具选择、边跳转、中断询问等离散决策，推理速度提升百倍，成本显著下降。
- **高置信快判，低置信升级（Human-In-The-Loop）**：
  置信度作为核心路由信号。当决策置信度低于阈值时，自动转交给慢思考主模型或触发人工审批（`interrupt` 通道）。
- **每轮低成本自改进校验（Every-turn Validation）**：
  自改进系统的最大风险在于“越改越乱”。通过 System 1 极便宜的打分能力，每轮为 Agent 的自改动（如新写的工具、修改的图结构）进行有效性实时评分，支持热回滚与版本快照。

### 2.4 极致解耦的应用层（以自适应 AI 教学助教为例）
- **传统助教痛点**：预置脚本死板，无法针对不同学科背景、不同理解层次的学生调整引导策略。
- **本项目自改进助教方案**：
  助教在与学生交互过程中，感知到学生在某个概念（如二叉树平衡旋转）存在理解障碍时，能够：
  1. 自主编写并热挂载一个针对该知识点的动态可视化/代码测试小插件；
  2. 动态调整提问引导流程图；
  3. 教学任务完成后评估教学效果，决定是否将该插件与流程固化至插件库。

## 三、 项目现状与已有技术积累

本项目已完成从上游应用提取通用内核的第一阶段工作，并建立了健全的开源代码底座：
- **项目仓库**：[`https://github.com/Asukayanamii/R-agent`](https://github.com/Asukayanamii/R-agent)

**已落地的基线能力**：
1. **工作流运行时**：基于 LangGraph 的核心调度流已稳定运行，具备上下文自压缩与历史检查点机制。
2. **事件总线系统**：基于 FastAPI 实现完备的 SSE 流式事件协议，事件流与图执行逻辑彻底解耦。
3. **安全工具集底座**：已内建并跑通 Bash 终端沙箱、文件差异比对（Diff）、精准局部编辑（Edit）、多模态文件读取等基础工具。
4. **可视化与测试基础设施**：提供一键启动的 Web 调试界面与本地桌面应用环境（PyQt/Webview），具备自动化测试用例。

**当前工程切入点**：
基础底座已就绪，当前正全面进入“从硬编码装配根向 Cordis 插件系统重构”以及“动态图拓扑注入”的攻坚起点。

## 五、 团队招募计划与画像

为推进国创项目立项与技术攻关，现公开招募志同道合的核心团队成员：

### 5.1 招募方向与分工

#### A. 图工作流与引擎架构方向（1~2人）
- **职责**：深入 LangGraph 内部机制，攻坚运行时状态机持久化、动态拓扑注入、动态通道创建。
- **技术偏好**：熟悉 Python 异步编程（`asyncio`），对图算法、状态机或工作流引擎（Temporal/LangGraph）感兴趣。

#### B. 插件容器与 Harness 工程方向（1~2人）
- **职责**：实现类似 Cordis 的生命周期管理，负责 Agent 自生成代码的沙箱隔离、热编译与依赖注入。
- **技术偏好**：熟悉模块动态加载（`importlib`）、面向对象设计模式、安全沙箱机制。

#### C. 决策模型与算法评估方向（1人）
- **职责**：负责 System 1 模型接入（如 Jev、TypeSafe 或小模型蒸馏路由）、置信度标定及自改进打分验证系统。
- **技术偏好**：了解机器学习/NLP 评估指标，关注 Fast Routing、Agent 评测前沿进展。

#### D. 应用层交互与示范落地方向（1人）
- **职责**：负责“自适应 AI 助教”等示范场景的原型搭建，设计直观展示“Agent 正在自我进化”的可视化前端界面。
- **技术偏好**：熟悉 Web 前端（Vue / React）或 Python 客户端开发，具备良好审美与人机交互设计意识。

### 5.2 基本要求
1. **扎实的编程习惯**：代码风格清晰，会使用 Git 进行分支管理与协作；
2. **强大的自驱力与学习饥渴感**：能够阅读前沿英文论文、官方技术文档及开源框架源码；

*说明：无需对所有框架都精通！只要对 Agent、LangGraph 或 Cordis 思想感兴趣，且具有出色的学习执行力，均非常欢迎加入！*
