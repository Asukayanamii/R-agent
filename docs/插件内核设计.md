# R-agent 插件化内核：固定锚点 + 受约束片段 + 一切皆插件

> **怎么落地看这份，为什么这么做看 README**——「目标形态：LangGraph 的执行图 × Cordis 的装配图」
> 一节讲了整合解决的痛点与理由，这份只讲机制与实施。
>
> 前置决定：
> - 内核内联 `app/kernel/`（不 import 任何 `app.*`，将来整体搬走只需挪目录）；
> - **一切皆插件**：loop（现在的图）、协议、Web 前端、工具箱……全都是 `app/plugins/builtin/` 里同级的插件；
> - 但插件分**必需**与**可选**两种：必需插件（loop / protocol / toolbox）**可替换、不可停用**；可选插件才可真卸下；
> - 片段内部结构有**允许集**：链 → DAG（禁逃逸边、禁条件边、禁环）；**不允许嵌套**；
> - **每条约束都必须有机制**：契约里没有这个字段（写不出来）／校验器拒绝（装载不了）／用例锁住（CI 看得见）——**不靠文档措辞**。

## 0. 一句话架构

> **插件的贡献 = 一个挂点（锚点）+ 一段受约束的内部结构；连"图长什么样"本身也是插件的产物。**
> Cordis 维护插件与其依赖；合成器把「loop 插件声明的骨架（含锚点）+ 挂在锚点上的片段」缝成**一张**具体 LangGraph；结构变化在回合边界原子替换。
> 节点是壳，实现从 Cordis 注入（抽象节点）。

三个层次各管一件事：

| 层 | 管什么 | 不管什么 |
| --- | --- | --- |
| Cordis 内核 | 谁活着、依赖谁、装上卸下的可逆性 | 图长什么样 |
| 插件（数据 + 代码） | loop 声明骨架与锚点；其他插件声明挂点、内部结构、通道、依赖 | 自己会被插到哪条边上、邻居是谁 |
| 合成器 | 校验、通道合并、锚点插链、编译、版本替换 | 插件内部逻辑 |

这套设计的五个要点：

1. **loop 也是插件**：它不享有特权代码路径，只享有**角色义务**（`role="base"`：提供锚点表与出站接缝表）——换成另一种 loop 就是换一个插件；
2. **锚点是图里的一等对象**：每个版本的图里都在（空着就是透传节点），"能挂在哪"直接从 `docs/graph.mmd` 看得见；`as_node=` 写入、resume 兼容判定、检查点布局全都锚在稳定的节点名上；
3. **结构是可序列化的数据** → 版本化、审计、回滚、渲染（mermaid）都是白拿的；
4. **表达力封顶靠契约而不是靠自觉**：路由写不出来（没有条件边字段）、嵌套写不出来（只能挂锚点）、改内核节点写不出来（没有 `replaces`）；
5. **失败与越界都靠机制**：装配失败不改变运行图、越界写入在装载前被拒、运行失败留痕并熔断、卸载残留由用例锁住。

**为什么不走单栈**（把 agent loop 也做成 Cordis 插件、执行图自研）：做得到——DSH 生态里已经有
可视化工作流编排插件（拖拽画布、断点续跑、运行中改画布）。不选它是因为要自己实现并自己保证
状态合并语义、持久化、暂停/恢复、确定性并行这四件事，而审批、沙箱授权、压缩锚点、历史恢复
现在已经全在检查点里。取舍写全在 README，这里不重复。

## 1. 已实测的框架事实（本稿规则的事实依据）

探针脚本一次性、不进仓库；**结论以本节为准**。本环境：Python 3.13.15、langgraph 1.2.11、
langchain-core 1.6.3。

### 1.1 设计前探针（3 条）

1. ✅ **动态 `TypedDict` 能当 StateGraph 的 schema**，编译与运行正常——"片段声明通道、合成时动态拼状态"框架层可行。
2. ⚠️ **未声明的键被静默丢弃，不报错**：写入过滤只认已声明的通道（嵌套下实测：子图写 `notes`、父层只声明 `x` → 结果只剩 `{'x': 2}`；补声明后回流）。**这条直接决定"通道合并必须做装载前校验"**。展平形态下复验结论相同，见 1.2-④。
3. ✅（备查）嵌套子图内的 `interrupt()` 会冒到父层 `snapshot.interrupts`，`Command(resume=...)` 可恢复。**本稿不走嵌套**，这条不是路径依赖。

### 1.2 阶段 0 探针（7 条，2026-10 本机实测）

① **锚点插链 + 条件边指向锚点：通过。** 条件边的源从 `agent` 改到 `post_model`（`post_model` 上挂了链就是链尾）后，`tools_condition` 分流照常；中断 `next` 语义不变（仍停在 `('tools',)`），`resume` 后沿锚点链继续、**链上节点不重跑**。超步：无工具轮 2→7（+5），一次工具轮 5→13（+8）。
② **透传锚点开销：可接受，不启用"空锚点折叠"。** 每轮新写：无工具轮 8→19 行（×2.38）、一次工具轮 16→33 行（×2.06）；`checkpoints` 行数=超步+1、`writes` 每步约 1~1.5 行，无额外放大；本地 SQLite 墙钟 ×2.3~2.4（探针含假模型，真实轮次里模型调用占大头，占比更小）。
③ **展平下的旧检查点：Go。** 真实库（19 个旧 thread）副本上，用"骨架形态的展平图"（节点实现是 app 真码）读：`history` 与旧图逐字段一致、`interrupts` 可读可 `resume`、`repair_after_abort` 后可继续对话；新图读旧 thread 时通道集合不膨胀。三条必须记住的语义：
   - **发新消息 = 从 START 走新一轮**，pending 的片段节点（如 `post_tools`）**不执行**；`astream(None)` 才是"从 pending 续跑"。旧图里两种解释等价（START 与 `tools` 的后续同名 `compact`），展平后差异才会露出来；
   - resume / pending 续跑**不经过 `stamp`**（不重跑 START）——旧 thread 因此**没有 `harness` 戳**，兼容判定按"无戳"缺省处理；
   - `aupdate_state(..., as_node="tools")` 在骨架图里写入的下一步是 `tools` 的新后继（`post_tools`），旧图里是 `compact`。
   （"中断所在节点在新结构里不存在"的报错路径**未实测**——它是 §4.4 的兼容判定，属于阶段 B 要实现的机制。）
④ **展平下的写入过滤：与 1.1-2 相同——静默丢弃、零日志、无报错**（连"声明通道写错类型"也不拦）。**装载前校验是唯一防线**，这条比原估计更硬。
⑤ **运行时 `bind_tools`：可行。** 真实 `ChatOpenAI` + 本地 mock 端点实测：`bind_tools(TOOLS)` 首次 11.5ms（schema 转换一次性），之后中位 0.10ms、p95 0.13ms；复用一次绑定与每次重建，请求体逐字段一致、usage 一致、无 WARNING 日志——**不需要"变更才重建"的优化**。
⑥ **`compile()` 成本：毫秒级。** 线性图：9 节点 2.2ms、30 节点 7.0ms、100 节点 23ms（有无 checkpointer 无差别）；骨架图（含条件边与 bind）10.75ms、现状图 6.11ms——"结构变化时重编译、回合边界原子替换"的代价可接受。
⑦ **表驱动资产路由：通过。** 一条动态路由 + 注册表：未装载 `/ui` 与 `/ui/` 均 404；装载后即时可用（含嵌套资源、content-type 正确）；换一份资产/卸载**立即生效**；全程 **Starlette 路由表条目数不变**；`../` 与编码变体、反斜杠路径穿越全部 404 无泄漏。

### 1.3 附带发现（真实缺陷，与探针同批发现）

- `app/agent/retry.py` 的 `_config_with_spy`：`astream`/`ainvoke` 下节点 config 的 `callbacks` 是**空 handlers 的 `AsyncCallbackManager`**，`list(getattr(existing, "handlers", []) or [existing])` 会把 manager 自己当 handler → `AttributeError: 'AsyncCallbackManager' object has no attribute 'run_inline'`。产品路径走 `astream_events`（handlers 非空）所以没暴露；**在非事件流上下文里跑真图（测试、后台任务）会踩**。修复很便宜（handlers 为空时不把 manager 当 handler），放阶段 A/B 顺手做。
- （阶段 D 发现并修复）`Schema._validate_instance(None)` 会把内部的 `MISSING` 哨兵当结果返回——`resolve_config` 把它直接交给插件，插件拿到的是 `object()`（症状：`TypeError: 'object' object is not iterable`）。已归一化为 `None` 并补用例；**教训**：所有"内部哨兵"跨越模块边界前必须归一化。
- （阶段 E 发现）`await ctx.plugin(...)` 等到的是**插件的返回值**（通常 `None`），**不是 fiber**。要留着卸载就必须先拿引用再 await：`fiber = ctx.plugin(...)`、`await fiber`、…、`await fiber.dispose()`。发现器第一版写成了 `fiber = await ctx.plugin(...)`——装载"成功"、卸载时报 `'NoneType' object has no attribute 'dispose'`，症状是**删了文件但贡献还在**（旧片段没撤销，重载还会撞 `FRAGMENT_DUPLICATE`）。
- （阶段 E 发现）内核日志的 `%` 格式化只认 `%s/%d/%i/%f/%o/%j` 与 `%%`，**不支持宽度与精度**：`'%.0f%%'` 会静默错位（`%.` 当字面量，后面每个占位符各吃错一个参数）。已写进 `logger._format_args` 说明；写法上先在 Python 里算好再进格式串。
- （阶段 H 发现）**画图 CLI 自阶段 D 起就是坏的**：`loop` 在 D 加了 `inject: ['model','summary_model','tools']`，而 `python -m app.harness` 从没装过 toolbox —— `ensure_essentials()` 直接报 "必需插件不可用：builtin/loop（PENDING）"。是这次"重排后重导图应与现文件一致"的验证抓到并修掉的；教训：**入口类小工具也要跟着装配契约的变更走**，否则它烂掉没人知道（它不在测试面里）。

**只展平**（见 §3.3）：所有节点与通道进同一张图 → 检查点布局、`next` 语义、`as_node=` 写入路径、事件流全都不变，**旧会话零风险**。

## 2. 契约（`app/harness/fragment.py`）

### 2.1 片段

```python
@dataclass(frozen=True)
class Fragment:
    id: str                                  # "builtin/loop"、"workspace/research"
    anchor: str                              # 挂点：loop 声明的锚点名（见 §2.4）
    nodes: tuple[NodeSpec, ...] = ()         # 无 edges 时：顺序即执行顺序（一条链）
    edges: tuple[EdgeSpec, ...] = ()         # 可选：片段**内部**的有向边（第二版启用）
    channels: tuple[ChannelSpec, ...] = ()
    order: int = 0                           # 同一锚点上的排序（相等则按装载顺序）
    role: str | None = None                  # "base"：声明自己是骨架（见 §2.6），当前恰好一个
    output_seams: tuple[str, ...] = ()        # 仅 role="base"：它保证产出的出站接缝（见 §2.7）
```

**片段内部结构的允许集**（由校验器执行，§3.1）：

| 允许 | 说明 |
| --- | --- |
| 链（无 `edges`） | 第一版的唯一形态：`nodes` 顺序执行 |
| DAG（有 `edges`） | 第二版：允许分叉后汇合、并行段（fan-out / fan-in） |
| **禁止逃逸边** | 边的两端都必须在片段内部。"资料不足就回 `agent` 重问"这种边 = 逃逸 = 拒绝：那等于把**路由权**交给插件，而路由是内核语义（`tools_condition`、以后的 System-1 路由都建在它上面） |
| **禁止条件边** | 分支走向由内核决定；片段内部只允许无条件边 |
| **禁止环** | "再来一轮"写在节点代码里（理由见 §11）：片段每次经过锚点都要跑完、不可暂停、没有人审批点，用图表达只会白付检查点开销并吃掉整轮步数预算 |

### 2.2 节点（含抽象节点）

```python
@dataclass(frozen=True)
class NodeSpec:
    name: str
    run: Callable | None = None              # 普通节点：自带实现
    interface: str | None = None             # 抽象节点：实现从 Cordis 服务名解析（二者恰有一个）
    reads: tuple[str, ...] = ()
    writes: tuple[str, ...] = ()
    impl_id: str = ""
```

- `interface` 就是"抽象节点"：**图里固定的是名字与位置，实现从服务解析**；
- 契约里**没有**"替换别人节点"的字段——"换实现"只能走 DI（换服务），换不了图上的位置。

### 2.3 通道

```python
@dataclass(frozen=True)
class ChannelSpec:
    name: str                                # 插件通道强制 "plugin.<fragment-id>.<field>"
    reducer: Callable | None = None          # 缺省 last-write-wins（现有 compaction/usage_anchor 的语义）
    default: Any = None
```

内置通道：`messages`(add_messages)、`compaction`、`usage_anchor`、`harness`（新增，见 §5.3）。

**写入权限是分级的**（校验器强制，不是口头约定）：

| 通道 | 谁能写 | 怎么保证 |
| --- | --- | --- |
| `messages` | **只有内核节点**（`agent` / `tools` / `compact`） | 校验器：插件节点 `writes` 里出现 `messages` → **拒绝装载** |
| `compaction` / `usage_anchor` / `harness` | 只有内核节点 | 同上 |
| `plugin.<fragment-id>.<field>` | 该片段自己 | 校验器：前缀必须等于自己的 id（防撞名） |
| 别人插件的 `plugin.*` 通道 | **只读** | 校验器：`writes` 里出现非自己命名空间的插件通道 → 拒绝 |

> 于是"锚点链不要改 messages，否则会影响路由"这句话**不需要写**——它已经在校验器里了。

### 2.4 入站锚点（5 个，位置决定能力）

```
START → stamp → [entry] → compact → [pre_model] → agent → [post_model]
                                                            ├─(有 tool_calls)→ tools → [post_tools] → compact
                                                            └─(无 tool_calls)→ [finish] → END
```

| 锚点 | 位置 | 触发频率 | 典型用途 |
| --- | --- | --- | --- |
| `entry` | stamp 之后、compact 之前 | **每轮 1 次** | 注入外部上下文、换入参 |
| `pre_model` | compact 之后、agent 之前 | **每次模型调用前** | 先查资料再写、改写发给模型的视图 |
| `post_model` | agent 之后、路由之前 | **每次模型输出后** | 输出护栏、改写、记录 |
| `post_tools` | tools 之后、compact 之前 | **每次工具执行后**（只有调了工具才走） | 评审/补全工具结果 |
| `finish` | 路由到 END 之前 | **每轮 1 次**（终结轮） | 本轮评估、收尾通知、写摘要 |

- **`finish` 是必需的不是可选的**：不调工具的轮次不经过 `post_tools`，少了 `finish`，"每轮都评"的评估类插件会整轮漏掉；
- **`post_model` 在路由之前**：条件边的**源**从 `agent` 改到 `post_model` 即可，路由函数一个字不动；
- **三处不能设锚点**：`stamp` 之前（会破坏"版本戳是本轮第一个写入"的不变量）、路由本身（插件不能决定"走哪条"）、`compact`/`agent`/`tools` 内部（那是服务事件的地盘）；
- **锚点不是内核常量，而是 loop 插件的声明**：它们由 `role="base"` 的片段提供，校验器对照**当前活跃 base 的锚点表**（§3.1 第 1 条）；换一种 loop = 换一张锚点表。

**锚点 vs 服务事件的分工判据**：这一步的产出需不需要**进检查点**（被前端看见、能回放、参与后续状态）？
要 → 挂锚点；不要（只改这一次调用） → 监听服务事件（轻，不出现在图里）。

### 2.5 六类接缝（插件不按类型分，贡献按接缝分）

一个插件可以同时贡献多类东西。判据问三个问题：改**顺序**、改**实现**、还是**某个动作的前后**？都不是 → 它是数据。

| 接缝 | 谁调用谁 | 贡献方式 | 生效时机 | 项目内例子 |
| --- | --- | --- | --- | --- |
| **结构** | 图调用它 | 片段挂锚点（可只声明通道、`nodes=()`） | 回合边界 | `pre_model` 上挂 research 链 |
| **实现** | 图调用它 | `inject` / 注册服务 / 替换服务 | 见 §4.3 的放宽/收紧 | 工具、审批名单、压缩策略、模型适配器、checkpointer |
| **拦截** | 图调用它 | `ctx.on(...)` 监听服务事件 | 即时 | 审批策略监听 toolbox 的 `tools/pre-execute` |
| **入口** | **它调用图** | 注入 `chat`/`runner` 句柄 + 登记 API 起后台任务 | 即时 | 远程控制插件（手机 / IM / 定时器） |
| **界面** | 内核服务它 | `ctx.assets.mount(alias, dir)` 提供静态资产 | 即时（表驱动） | Web 前端插件（`/ui`） |
| **不是插件** | 都不 | 写文件 | 下一轮 | 技能 `SKILL.md`、`AGENTS.md` |

**入口类插件的三条必须定清楚**（否则一上线就是坑）：

1. **会话归属**：远程来的命令必须**显式配置**落在哪条会话、哪个工作区——不能沿用本地 UI 那个"当前工作区"语义，远程来源跟本地用户不是同一信任级别（内核校验配置，插件自己说了不算）；
2. **审批怎么落地**（最要命的）：远程发起的调用一旦触发 `interrupt`，远端没有确认卡片可点 → **死锁**。三选一：插件自己转发确认卡片并回填 `resume` / 限制远程来源的能力集（不触发审批的才放行）/ 停在待确认 + 推提醒，等本地 UI 上的人处理；
3. **留痕**：远程触发的对话就是一条**普通会话**，出现在会话列表里、带完整 tool 轨迹。

**界面类接缝的卸载语义（机制，不是措辞）**：内核只挂**一条动态资产路由**（`/ui/{path:path}`），它查"当前活跃插件里 alias 为 `/ui` 的是谁"→ 解析文件。装载/卸载只改这张表，**不动 Starlette 的路由表**（运行时增删路由没有正式 API，也是一个已知坑）。卸载后同一 URL 返回 404；桌面端（pywebview 加载 `/ui`）会明确看到失败而不是白屏。

### 2.6 必需插件 vs 可选插件（"可拆卸"的精确含义）

| 类别 | 成员 | 可替换 | 可停用 | 缺了会怎样 |
| --- | --- | --- | --- | --- |
| **必需** | `loop`、`protocol`、`toolbox` | ✅ | ❌ | **启动失败并报明原因**（吸收早期失败，不带着半死的内核跑） |
| **可选** | `compaction`、`approvals`、`context`、`exporters`、`webui`、工作区插件 | ✅ | ✅ | 功能退化，其余照常（如 `COMPACTION_ENABLED=0` 的现有语义） |

必需性由**装配脚本**声明（`ctx.plugin(..., essential=True)`），启动时校验"必需的都在 ACTIVE"，否则抛错。所以：

> **"前端可拆卸"= 可以换一份前端插件（`webui` 是可选项，卸下只丢 `/ui`，`/chat/*` 照常）；
> "协议可拆卸"= 可以换一份协议实现（换 wire format），但停用协议 = 没有对话能力，所以它是必需项。**

### 2.7 出站接缝（协议依赖的东西）

与入站锚点对称：内核在**固定的输出点**上产出，协议把它们映射成 wire 形状。这些输出点由 `role="base"` 的插件**保证产出**（`output_seams` 义务），协议依赖的是**这张表**，不是整张图：

| 输出点 | 产出 | 现有对应 |
| --- | --- | --- |
| 回合开始 | 会话握手 | `thread` |
| 模型输出增量 | 文本 delta | `text_delta` |
| 模型调用结束 | usage / message_id | `message_end` |
| 工具调用开始 / 结束 | 调用、结果、失败标记、结构化 diff | `tool_start` / `tool_end`（`ok=false`、`diff`） |
| 待确认 | interrupt 载荷 | `interrupt` |
| 压缩发生 | 压缩记录 | `compact` |
| 回合结束 | 结束标记 | `done` / `error`（唯一出口） |

- 插件挂的片段**默认不产出事件**；要产出就声明自己的命名空间事件（`plugin.<id>.<event>`）；
- 前端对未知类型**静默忽略**（现有约定）——这条约定正好让"插件扩展"与"前端稳定"并存：插件加事件不用改前端，前端不认识也不会崩；
- **输出点的集合随内核版本走**，不随插件变化——否则前端会被"某个插件在不在"搞崩。

### 2.8 两种依赖：服务依赖 vs 契约依赖

| 依赖 | 表达 | 判定时机 | 例子 |
| --- | --- | --- | --- |
| **服务依赖** | `inject: ["tools"]` | 运行时：提供方缺失 → 该插件 **PENDING**（不进合成） | 片段依赖工具箱服务 |
| **契约依赖** | `requires: "protocol:v1"` / `"loop:v1"` | **装载时**：版本不满足 → **拒绝装载**（不是 PENDING——形状不对等不来） | webui 插件依赖协议插件的形状 |

浏览器里的前端**没法 inject 一个 Python 服务**——它依赖的是**形状与版本**，所以走契约依赖。兼容规则：
**加字段、加事件类型 = 非破坏（不 bump）；改语义、删字段 = 破坏，bump 版本，依赖方必须跟着升**。

## 3. 合成器（`app/harness/composer.py`）

```
输入：Cordis 里处于 ACTIVE 的插件所贡献的 fragments（含 loop 这份 role="base" 的）
  → 收集与两段校验（注册期静态 / 装配期图级）
  → 通道合并（命名空间 + reducer 一致性 + 写入权限分级）
  → 锚点插链（在 base 声明的锚点位置上把片段接进骨架的边）
  → 动态拼 StateDict schema        ← §1.1-1 已证可行
  → 构建 StateGraph → 展平 → compile
  → GraphVersion(id, structure_hash, spec, impls)
```

### 3.1 校验：分两段，都是"失败不改变运行图"

**注册期（静态，不通过 = 不装载；文件留着，报明原因与改法）**

1. 锚点不在**当前活跃 base 片段的锚点表**里 → 报出可用锚点；base 不在（PENDING/失败）→ 报"等待 loop 就绪"；
2. 片段内部结构违反允许集：悬空边 / 逃逸边 / 条件边 / 环（§2.1）；
3. **写入权限**：`writes` 含 `messages`/`compaction`/`usage_anchor`/`harness` → 拒绝；含别人命名空间的 `plugin.*` → 拒绝；自己的通道前缀不等于自己 id → 拒绝；
4. 契约依赖版本不满足（`requires` 与提供方声明的版本不匹配）；
5. 通道的 `reducer` 与已声明的同名通道不一致；节点名与骨架或已装载片段冲突。

**装配期（图级，拒绝装配，保持当前运行图不变）**

6. **整图连通性**：`START` 恰好一个后继、每个节点从入口可达、每个节点都能到 `END`、无孤儿/死路；当前"链"形态下几乎不可能失败，所以它是**内核断言**，启用片段内 DAG 后升级为真检查；
7. **骨架完整性**：恰好一个 `role="base"`；它的必需节点（`stamp`/`compact`/`agent`/`tools`）与锚点齐全；它承诺的 `output_seams` 覆盖内核最小集合。

**警告（装配成功但要明说）**

8. **写了没人读 / 读了没人写**的通道（§1.1-2 / §1.2-④ 那条静默丢弃的存在理由）；
9. 同一锚点上挂了多个片段（说明链顺序与依据）；
10. 因依赖未就绪（`inject` 缺服务）而**未参与合成**的片段——Cordis 的 PENDING 是静默的，必须点名报出："research 未激活：缺少服务 search"。

### 3.2 合成报告（由代码生成，不是人写的）

```
图 v7  结构哈希 9f3c…   骨架: builtin/loop@v1   协议: builtin/protocol@v1
参与: builtin/loop, builtin/toolbox, builtin/compaction, builtin/protocol, builtin/webui, workspace/research
未参与: workspace/search  ← 原因：缺少服务 search
停用: workspace/probe     ← 原因：连续失败 3 次（熔断，见 §4.2）
挂载: entry     ← （空，透传，每轮 1 次）
      pre_model ← chain@0 research（写 plugin.research.notes；每次模型调用前）
      post_model← （空，透传，每次模型输出后）
      post_tools← （空，透传，每次工具执行后）
      finish    ← （空，透传，每轮 1 次）
生效时机: 能力类变更已即时生效；结构变更随本版本在本轮之后生效
警告: 通道 plugin.research.notes 暂无读取者
```

报告是 dataclass → JSON 生成的结构化对象（不是拼字符串），同时供：日志、`graph_updated` 事件、`inspect_graph` 工具。**"生效时机"、骨架与协议版本、每个挂载点的触发频率都是生成的字段**——不存在"忘了写"。

### 3.3 实现策略：只展平，禁嵌套

- **展平**（唯一策略）：所有节点与通道进同一张图 → 检查点布局、`next` 语义、`as_node=` 写入路径、事件流全都不变。旧会话兼容**已按决定放弃**（阶段 C）：结构变更后旧会话不承诺可续、需要就新开——展平只是实现形态，不构成兼容承诺；
- **不提供嵌套**：不引入命名空间、不给"未声明键在层间静默丢弃"留口子、`as_node` 写法不变；
- 代价与收益都写明：牺牲拓扑自由度，换来"任何变更都只是某锚点上多了/少了/换了什么"。

### 3.4 每条约束的落地机制（规则 → 机制对照表）

**原则：能不能做某件事，由契约的字段与校验器决定，不由文档措辞决定。**

| 要保证的事 | 靠什么落地 | 违反时会发生什么 |
| --- | --- | --- |
| 插件不能改路由 | 契约里没有"条件边"字段 | 写不出来（字段不存在） |
| 插件不能嵌套 | 契约里没有嵌套字段，只能挂锚点 | 写不出来 |
| 插件不能改骨架节点 | 契约里没有 `replaces`；骨架节点由 base 插件声明 | 写不出来 |
| 插件不能造新锚点 | 校验器：`anchor` 必须 ∈ 当前 base 的锚点表 | 拒绝装载，报出可用锚点 |
| 边不许逃逸 | 校验器：边两端必须在片段内 | 拒绝装载，点名逃逸边 |
| 插件不能写 `messages` 等内核通道 | 校验器：写入权限分级（§2.3） | 拒绝装载 |
| 插件通道不许撞名 | 校验器：`plugin.<fragment-id>.<field>` 前缀强制 | 拒绝装载 |
| 同一通道不许有两种合并语义 | 校验器：同名通道 `reducer` 必须一致 | 拒绝装载 |
| 前端不许对错协议 | 校验器：`requires: "protocol:vN"` 版本判定 | 拒绝装载 |
| 骨架必需节点不许缺 | 装配期骨架完整性校验（§3.1 第 7 条） | 拒绝装配，**运行图不变** |
| 整图必须连通 | 装配期连通性校验 | 拒绝装配，**运行图不变** |
| 必需插件不许缺 | 启动期校验 `essential` 清单 | **启动失败**，报明是哪一个 |
| 报告不许漏字段 | 报告是 dataclass → JSON 生成 | 少字段 = 代码跑不过 |
| 放宽类变更不许一轮内变 | 能力快照**绑在租约上**（回合开始取一次） | 设计上不可能 |
| 坏节点不许打死会话 | 节点壳收口（§4.2）：异常 → 空更新继续 | 会话继续，前端留痕 |
| 坏节点不许变成幽灵 | 熔断：连续失败 3 次 → 摘出合成输入 | 自动停用 + 报告点名 |
| 卸下不许残留任务/连接 | 登记 API（`ctx.spawn` / `ctx.resource.acquire`）+ **用例锁住** `asyncio.all_tasks()` 快照 | 用例失败（CI 可见） |
| 卸下不许留下能访问的资产 | 资产路由是**表驱动**（卸载即从表里移除） | 同一 URL 立刻 404 |
| 授权文件不能被 agent 自己改 | 沙箱 deny 列表（§5.2） | 硬阻断，永不提示 |
| **插件不许做不可逆副作用** | **部分**：登记 API 是唯一拿任务/连接句柄的正路 + 卸载残留用例 | **恶意绕过拦不住**——与 bash 沙箱同一定位，明写在 README |

## 4. 运行时：抽象节点、失败收口、生效时机

### 4.1 抽象 `tools` 节点（保留原位，零重建路径）

`tools` 节点**留在骨架原位**（`agent ⇄ tools` 的环不动），只把它抽象化：

- `app/agent/tool_calls.py` 的 `run_tools` 现在读模块级 `TOOL_MAP` / `APPROVAL_REQUIRED`，改为**闭包注入**：`partial(run_tools, registry=ctx.tools, approvals=ctx.approvals)`；
- 节点每次调用时 `registry.snapshot()` → 新增工具**不需要重建图**；
- `call_model` 里的 `model.bind_tools(TOOLS)` 改成**每次调用前**对实时快照 bind（本地构建，无网络）；
- **结构版本与能力集分开记**：结构进 `GraphVersion`，工具集快照进"能力清单"，变更时发 `toolset_updated` 事件。

（每次 bind 的实际代价、缓存与告警：阶段 0 探针 5 实测——见 §1.2 ⑤：每次重建 0.1ms，请求体与 usage 不变、无告警。）

### 4.2 节点壳：冻结快照 + 失败收口 + 熔断

图里的普通节点**按值绑定**：合成那一刻，节点实现（自带的 `run`、或从 `interface` 解析出的服务对象）就写进 `GraphVersion.impls`，随编译**直接绑进图**——运行期没有"节点名 → 实现"的查表。进行中的回合钉在自己的版本上，永远读到旧实现（一致）；重合成产生的版本只在回合边界替换（§4.4），而重合成只由**片段集合或熔断名单**的变化触发——只改实现（如提供方 `.py` 热重载）不会换图，新实现要等下一次重合成才被捕获。

**插件节点失败时退化到最小 loop**（跳过这一步继续跑骨架环），四条护栏全部在壳里实现：

1. **只对插件贡献的节点生效**：骨架节点（`agent`/`tools`/`compact`）崩溃照旧上抛——那是内核 bug，吞掉就是掩盖真问题；
2. **绝不能吞 `GraphBubbleUp`**：`interrupt()` 抛的就是它、且它继承 `Exception`——壳里 `except GraphBubbleUp: raise` 排在最前（`tool_calls.py` 里那句"这句不能删"的注释就是为这个留的）；
3. **留痕**：日志 WARNING + 一条前端可见的事件 + 状态里记一笔（哪个片段、哪一步、异常原文）——三处都写；
4. **熔断**：连续失败 3 次 → 该片段**自动摘出合成输入** + 报告点名 + 前端提示"因连续失败已停用"，修好再装载。阈值硬编码。

失败计数是**片段级**的：一个片段里任一节点连续失败 3 次即熔断整条片段——片段是一个语义单元，半条链比没有链更危险。

### 4.3 生效时机与触发频率

| 贡献 | 生效时机 | 触发频率 |
| --- | --- | --- |
| 结构（片段挂锚点） | **回合边界** | 看挂哪：`entry`/`finish` 每轮 1 次；`pre_model` 每次模型调用前；`post_model` 每次模型输出后；`post_tools` 每次工具执行后 |
| 能力（DI 服务） | 见下面"放宽 / 收紧" | 被读的时候：模型调用前 bind、工具执行时、压缩判定时 |
| 拦截（服务事件） | 即时 | 每次该动作发生 |
| 入口（自带任务） | 即时 | 它自己的节奏 |
| 界面（资产） | 即时（表驱动） | 每次请求 |

| 变更 | 生效时机 | 怎么保证 | 理由 |
| --- | --- | --- | --- |
| **放宽类**（加工具、放宽权限、加链） | **回合边界** | 能力快照绑在租约上 | 改变的是"模型看到什么/走到哪"，语义要整齐 |
| **收紧类**（移除工具、收紧审批、撤销授权） | **即时** | 每次判定重新读 | 安全闸门，晚一步都可能出事 |
| 观测类（日志/导出/审计） | 即时 | 事件监听 | 不影响行为 |

一句话：**凡改变"模型看到什么、走到哪"的，都在回合边界；凡属于安全与观测的，都即时。**

**一轮对话的实际执行序列**：

```
回合开始 —— 租约获取：决定用哪个图版本；能力快照在此刻冻结
  START → stamp（写 harness{version}）
  → entry 链          每轮 1 次
  → compact 第 1 次 → pre_model 链 第 1 次 → agent → post_model 链 第 1 次
        ├─ 无工具调用 → finish 链 → END
        └─ 有工具调用 → tools（审批在这里读收紧类快照）
                          → post_tools 链 第 1 次
                          → compact 第 2 次 → pre_model 链 第 2 次 → agent → post_model 链 第 2 次 …
```

三个容易踩的点：**`pre_model`/`post_model` 是"每个模型回合"一次，不是每轮一次**（想每轮一次挂 `entry`）；**`entry` 在 resume 时不重跑**；**resume 用当前版本继续**（前提：中断所在节点在新结构里还在），stamp 保留原戳供审计。

### 4.4 版本与租约（守恒，跟抽象层级无关）

- `pending → 校验+编译 → 原子替换 current`，**只在回合边界**（租约获取时）发生；
- `LangGraphRunner` 的所有路径（`stream`/`resume`/`compact`/`repair_after_abort`）先 `async with lease(thread_id)`；
- **resume 兼容判定**：待确认中断所在**节点名**在新 spec 里存在 → 允许；否则明确报错 + 提供"放弃待确认"出口（现有 `repair_after_abort` 明确不动待确认会话，这条出口目前不存在，要补）；
- 旧版本回收：无在飞租约 + 其上无待确认中断 + 未超 LRU（默认 4）。

## 5. 插件宿主与信任

### 5.1 目录约定（对齐 `skills.py` 的做法：约定式发现 + 两级根）

| 来源 | 路径 | 内容 | 信任 |
| --- | --- | --- | --- |
| 内置 | `app/plugins/builtin/` | loop / 协议 / 前端 / 工具箱 / 压缩 / 审批 / 上下文 / 出口 | 内核自带 |
| 全局 | `~/.r-agent/plugins/` | `*.py`（可编程）/ `*.json`（纯声明片段） | 用户目录，装载即信任 |
| 工作区 | `<workspace>/.r-agent/plugins/` | 同上 | **默认关**，首次需审批，按工作区持久化 |

**两种文件同一个目录**：`.py` 走 Cordis 全能力（注册服务、监听事件、贡献片段、起后台任务、挂资产）；`.json` 是**纯片段声明**（结构数据，不执行代码）——后者是给 agent 自己写用的安全形态（阶段 E），前者是给人写的。

### 5.2 前置修复：授权文件必须进禁区（现有洞）

`guard_path` 的 deny 列表只有 `.env` / `.git` / `data`，**`.r-agent/sandbox.json` 不在里面**——agent 可以自己写这个授权文件（当场不生效，因为 `_memory` 缓存优先；**重启后被采纳**，是真实的持久化越权路径）。插件授权文件会落在同一位置，所以这条必须先修：`DENY_READ`/`DENY_WRITE` 加入 `<workspace>/.r-agent/sandbox.json` 与插件授权文件；补用例锁住（硬阻断、永不提示）。

### 5.3 结构戳（`harness` 通道）

装配器强制注入内置 `stamp` 节点（`START → stamp → entry → …`，由 base 插件声明、校验器保证在位），每轮开始写 `harness: {version, structure_hash, at, base, protocol}`。resume 不重跑 START，所以"被中断那一轮的结构戳"留在检查点里，兼容判定读它。**旧 thread（本版本之前产生的会话）没有这个戳**（阶段 0 实测），兼容判定按"无戳"缺省处理。新增通道对旧检查点安全（已实测）。

### 5.4 加载、热重载、卸载

- 加载：`app/kernel/loader` 的 `compile + exec` 直读源码（绕开 importlib 的"同秒等长"字节码缓存坑，上游已有测试锁住）；
- 热重载：mtime 轮询（Windows 上不依赖 inotify）→ dispose 旧 fiber → 重新装载 → 合成器标脏 → 下一回合生效；
- 卸载宽限期：先从合成输入里摘掉（新回合不再进入），等在飞租约归零再真正 dispose（effect 逆序释放）；
- **登记 API 是拿资源句柄的正路**：后台任务用 `ctx.spawn()`、长连接用 `ctx.resource.acquire()`、静态资产用 `ctx.assets.mount()`（都登记为 effect，卸载时统一 cancel / close / 摘表）。

### 5.6 插件配置（谁声明、谁合并、什么时候生效）

**配置项由插件自己维护**：新插件在做插件时就把可配置项声明成 `Config`（schema：名字、类型、
默认值、说明）并给出 `default_config()`——**不动内核、不动根配置模块**。默认值引用总体配置
（`.env` 里的 `COMPACT_*` / `SKILLS_*` 等），所以"改一处"的习惯照旧，但配置的**所有权**在插件手里。

合并与生效：

- 装配脚本负责把 **base（`default_config()`）与用户覆盖 dict 合并**后交给插件——
  这就是"用户在前端改设置"的落点：前端写的是**覆盖层**，不改 `.env`、不改代码；
- 覆盖层的存储形态（单文件按插件名分节，还是每个插件一个配置文件）等做设置界面时再定；
  倾向单文件：一次原子写、校验与回滚都只有一处；
- 变更通过**重载插件**生效（§5.4 的语义），感观由插件的**读取点**决定：审批名单是每次执行现取
  （收紧类，即时生效）；压缩/上下文这类旋钮在插件装载时定格（随结构版本，回合边界生效）；
- `Config` 校验不过 = **装载失败**（拒绝装载并报明原因），不是静默退回默认值。

与"三处同步"的关系：**只有当某个配置项同时暴露为 `.env` 全局项**（如 `COMPACT_AT`）时，
才仍走 `app/common/config` + `.env.example` + README 配置表三处同步；**纯插件配置项**
（如 `builtin/approvals` 的 `required`）不进根配置，文档写在该插件自己的人读说明处。



- 审批**在回合内**发生（走现成 `interrupt()` 通道：模型调 `install_plugin` 时弹卡）；
- 生效**在回合边界**（结构）/ **即时**（收紧类、界面、观测类）。所以不存在"批准到一半图就变了"，也不存在 agent 在同一回合里用上自己刚写的结构（这是刻意的，不是 bug）。

- `runtime.py`：`current_workspace` 这个 ContextVar 是内核机制；
- `langgraph_runner.py` 与 `runner.AgentRunner` 协议：内核门面，`api`/`service` 靠它活着，插件坏了没兜底（`StubRunner` 例外，它属于"换 Agent 实现"）；
- `tool_calls.py` 的**并行 / 取消 / interrupt 编号对齐**：正确性关键路径（"抛最早发生的异常"那条注释就是为它写的），换实现极易破掉"恢复值与卡片一一对应"；
- 版本与租约、合成器、校验器、协议里的 `error` + `done` 唯一出口：内核机制。

`app/container.py` 从手工装配变成**装配脚本**（一串 `ctx.plugin(...)`，必需项标 `essential=True`），`AsyncExitStack` 继续管 DAO/checkpointer 生命周期；`AGENT_STUB=1` 时只装配最小集（不装插件树）。

## 7. 目录与分层（目录顺序 = 依赖方向）

```
app/
├─ kernel/          L0 通用插件内核（零 app 依赖，整体可搬走）
├─ harness/         L1 装配层
│  ├─ fragment.py   Fragment / NodeSpec / EdgeSpec / ChannelSpec（纯数据，可 JSON 化）
│  ├─ events.py     事件词汇表（图的产出形状，与 OUTPUT_SEAMS 同侧，随内核版本走）
│  ├─ composer.py   收集 → 两段校验 → 通道合并 → 锚点插链 → 动态 schema → 构建 → compile
│  ├─ versions.py   pending/current、租约、兼容判定、回收
│  ├─ assets.py     资产注册表 + 一条动态资产路由（表驱动，装卸不动路由表）
│  ├─ circuit.py    失败账本 + 节点壳（插件节点收口，骨架节点上抛）
│  └─ runtime.py    HarnessRuntime：LangGraphRunner 的唯一入口（骨架插件经 base= 传入）
├─ agent/           L2 运行时：节点、模型、提示词、工具、沙箱、压缩
├─ plugins/         L3 插件
│  ├─ builtin/
│  │  ├─ loop/        骨架 + 锚点表 + output_seams
│  │  ├─ protocol/    接缝映射 + SSE 编码（provides protocol:v1；事件词汇表在 harness/events.py）
│  │  ├─ webui/       static/index.html（requires protocol:v1，alias /ui）
│  │  ├─ toolbox/  compaction/  approvals/  context/  exporters/
│  │  └─ model/  retry/  store/  sandbox/     ← 模型适配器 / 重试策略 / 存储 / 沙箱策略（§6）
│  └─ discover.py   两级插件库的发现 + 信任判定 + 声明文件解析 + 热重载
├─ web/             L4 宿主：api（表现）/ service（业务）/ handler（异常出口）
│                   + result / constant（宿主侧响应封套）——存储层已拆进 builtin/store（阶段 K2）
├─ common/          跨层叶子：config / exceptions / models（谁都能用，它谁也不依赖）
└─ main.py  desktop.py  container.py   进程入口 + 装配根（顶层，一眼可见）
```

摆放规则（README「分层」同步）：

1. **内核侧四层的顺序就是依赖方向**：kernel → harness → agent → plugins；逆向 import = 违规；
2. **叶子按其使用者归属**：只有宿主用 → `web/`（result / constant）；两层以上都用 → `common/`；
   `common` 只收"不 import 任何 `app.*`"的叶子——它出现第一个 app 内依赖就说明放错了；
3. **入口与装配根豁免**：`main.py` / `desktop.py` / `container.py` / `harness/__main__.py`；
4. 唯一的显式例外：`web/api` 经 `app.container` 取服务（服务定位器，装配根是唯一的全局句柄）；
5. 约束由用例守住：`tests/test_layout.py`（ast 扫 import，按允许矩阵断言，含 web 内部 api→service→dao）——
   **改错地方会红**，不靠文档措辞。

原先"`app/` 下每个关注点都是一级包"的约定（A–E 阶段）到此为止：顶层 13 个平铺包看不出层次，
也看不出谁依赖谁。现在每个关注点仍是独立包，只是**归了组**。

**三层插件化的边界与触发条件**（现在不拆——判据同样是"有第二个实现"）：

| 未来插件 | 拆什么 | 需要什么机制 | 触发条件 |
| --- | --- | --- | --- |
| ~~`builtin/store`~~ | ✅ 已拆（阶段 K2）：checkpointer + 索引/工作区 DAO + 审计 | — | — |
| `builtin/httpapi` | 路由注册（`web/api`） | 内核侧加一个"路由注册"服务（main 建好 app 后交表；同 `assets` 的表驱动形态） | 出现第二种前端 / API 形态 |
| `builtin/chat` | chat 服务（业务编排） | 无（`chat` 已是服务名） | 出现第二种应用形态 |

拆到那一步时，`web/` 这个分组会自然消失（树回到"内核侧 + 插件 + common + 入口"）。

1. `pytest tests/kernel -q` 全绿；阶段 B 的 golden 事件序列比对；
2. 端到端：装载/卸载/改文件三条路径，观察 ①日志里的合成报告（含骨架/协议版本、未参与、停用、生效时机、频率）②`graph_updated` 事件 ③`docs/graph.mmd` ④下一回合实际行为；
3. **插件化验收**：换一份 `webui` = 换前端；停用 `webui` → `/ui` 404 而 `/chat/*` 照常；`requires` 对不上 → 拒绝装载；
4. 可逆性：装载前后同一 thread 的 `history()` 与检查点对比，确认无残留通道影响后续回合；
5. 失败路径：插件节点抛异常 → 会话继续 + 留痕；连续 3 次 → 自动停用；装配校验失败 → 运行图不变 + 报错原文；`GraphBubbleUp` 照常上抛；
6. 兼容性：造"待确认中断 + 卸载该片段"，确认得到明确错误而非静默卡死，且"放弃待确认"能恢复；
7. 越权与残留：`.r-agent` 下授权文件写入被硬阻断；装载→卸载后 `asyncio.all_tasks()` 快照一致。

## 11. 风险与开放问题

- **"可拆卸"的含义要守住**：必需插件（loop / protocol / toolbox）是**可替换**不是**可停用**——停用协议就没有对话能力，所以它进 essential 清单，缺了启动就失败。可选插件（含 webui）才真的能卸下而不伤主链路。
- **协议拆成插件 = 跨插件契约变更**：改事件形状要同时改协议插件与前端插件。缓解：**加字段/加事件类型不算破坏**（前端未知类型与未知字段都忽略），只有改语义/删字段才 bump 版本；版本号写进 `harness` 通道与合成报告，便于对账。
- **界面类资产不做运行时增删路由**（Starlette 没有正式 API）：一条动态路由 + 注册表查表，卸载即 404；桌面端跟随 `webui` 插件，停用时看到的是明确失败而不是白屏。
- **表达力封顶是有意的**：插件不能改路由、不能嵌套、边不许逃逸、不能加环——全部由契约字段与校验器保证（§3.4）。
- **为什么循环不进图**：图级结构只用来表达"内核需要看见的东西"（可暂停、可恢复、可审计、要参与状态）。片段每次经过锚点都要跑完、不可暂停、没有人审批点，用图表达只会白付检查点开销并吃掉整轮步数预算。
- **锚点开销**：阶段 0 探针 2 实测（§1.2 ②）：无工具轮超步 2→7、写入 ×2.38；一次工具轮 5→13、×2.06；本地墙钟 ×2.3~2.4。量级可接受 → **不启用"空锚点折叠"**（折叠的代价是锚点名不再每个版本都在、稳定性打折，比这点开销贵）。
- **提示词缓存**：结构或工具集变化都会动 tools 段与系统提示前缀。缓解：变更收拢到回合边界一次提交；`graph version` 放系统提示最末（摘要之后）。
- **不可逆副作用的边界（诚实版）**：进程内拦不住恶意插件（Python 里 `import os` 就出去了）——能用机制保证的只有两件：**登记 API 是拿任务/连接/资产句柄的正路**、**卸载残留有用例兜底**。恶意那条线的闸门是审批 + 信任分级，和 bash 沙箱一模一样。
- **通道命名空间**：全展平意味着所有插件通道进同一张 schema，靠前缀校验防污染（§2.3）。
- **熔断阈值 3 次硬编码**：不给配置项。
- **插件不是越多越好**：多一个插件就多一份装载顺序、依赖与失败模式。只在"有第二个实现"或"要按场景开关"时拆（§6 的判据）；纯函数、内核机制、正确性关键路径一律不拆。
- **决策模型是插件，决策点不是**（System-1 的落位）：接 Jev 类模型时，**适配器**做成插件（`builtin/system1`），而"在哪问、问什么、置信度多低升级人工"属于路由语义、留在内核——与"路由权不交给插件"是同一条原则。
- **旧会话兼容：已放弃**（阶段 C 决定）。展平合成下实测旧检查点能继续读、能续跑（§1.2 ③，真实库副本验证过），但项目**不再把它作为需求**：不为"改完结构旧会话还能接着聊"设约束、不写兼容用例，结构变更后旧会话可弃。README 痛点表已同步改口径。
- **协议形状的静态引用：已解决**（阶段 H 把事件词汇表搬进 `app/harness/events.py`）。词汇表是**内核的产出契约**
  （与接缝表同侧），协议插件只负责映射与编码——`api`/`service`/`agent` 的静态引用因此是向下依赖，合法。
  换一份协议实现 = 换 mapping/encoding，事件名是前端契约、不随插件变。
- **内置插件四个：已拆**（阶段 K1/K2：`model` / `retry` / `store` / `sandbox`）。连同 A–E 的八个，
  现在共十四个内置插件；`app/web/dao/` 随之消失（宿主只剩 api + service）。
- **替代路线长期存在**：DSH 生态里已有能跑的执行图实现（可视化编排、断点续跑）。契约刻意不含 LangGraph 特有概念（而 loop 本身就是可替换插件），就是为了将来真要换执行图实现时，片段、协议与前端都不用重写——但它不是当前的待办。

## 12. 打包与配置分层（阶段 M：部署形态）

**两种运行形态共用一套代码**：源码（`python run_desktop.py`）与打包件（PyInstaller onedir）。
差别只在"应用目录/默认落点"，由 `app/common/config` 一处判定（`sys.frozen`）：

- `APP_DIR`：打包后 = 可执行文件所在目录，源码 = 项目根；相对路径配置都锚定它
  （所以"从哪个目录启动"不影响落点——这条从 A 阶段起就没变过）；
- 打包形态的**默认落点**全部指向用户目录（`~/.r-agent/{plugins,skills,data}`），源码形态维持原样：
  老用户的位置一个字节都不动；
- 三层配置：**真环境变量 > 用户级 `~/.r-agent/.env` > 应用级（安装目录旁的）`.env` > 默认值**。
  用户级配置在打包形态首次启动自动生成，**每一行都注释掉**——生成一份"全部生效的空配置"
  会盖掉别处的设置，表现是"改了没反应"（与 §5.6 的配置所有权是同一条原则）；
- `library_paths()` 把五处位置（应用目录/用户配置/插件库/技能库/会话库）在启动日志里打出来：
  打包后最常被问的就是"我的库在哪"。

**打包件现场验收**（真 exe、真模型、真 HTTP；`packaging/r-agent.spec`）：

- 安装目录旁的 `.env` 把三处库全指到外部文件夹（`D:\project\r-agent-deploy\`）；启动日志确认
  应用目录/用户配置/插件库/技能库/会话库都是预期位置，外部插件库的 `deploy_marker.py`
  与外部技能库的 `demo-report` 都生效；
- 让 agent 在工作区里做一版自己的前端插件（`.py` + `panel/index.html`，走确认卡）→ `GET /panel/` 200；
  再让它改展示效果（深色 + 两栏）→ **同一个地址当场返回新页面**（资产按请求读盘，不重启、不等边界）——
  这是"运行时动态改自己的前端"的判据；
- 顺带修掉三处（各有用例）：
  1. **导入即改全局日志**：`app/main.py` 在模块级 `basicConfig` + `setLevel`，任何 import 它的代码
     （测试、CLI）都会把 `app.*` 的 DEBUG 压没——挪进 lifespan；
  2. **SKILL.md 的 BOM**：Windows 编辑器/PowerShell 写的文件首行不是 `---` → frontmatter 解析失败 →
     技能"凭空消失"（产品行为是对的：告警不静默，但 BOM 是白拿的容错）→ 用 `utf-8-sig` 读；
  3. **插件名重复后缀**：模型传 `name="panel.py"` → 落盘 `panel.py.py` → 名字里已有后缀就不再补。
  4. **密钥会被打进对话**：模型一句 `env | grep -i plugin` 就把 `LLM_API_KEY` 变成工具输出 → 进会话记录、
     随请求发到模型服务（两次实测都被网关以 400 拒掉、整轮对话断）。`read`/`grep` 对 `.env` 有硬阻断，
     `env` / `echo $X` 没有 → 在**工具输出出口**（`invoke_call` 的两条返回路径）加按名字认密钥的遮蔽
     （`*_KEY` / `*_TOKEN` / `*_SECRET` / `*_PASSWORD` …，长度 ≥ 8 才算），覆盖所有工具、不必枚举绕法。

**诚实记录**：桌面窗口那条路径没在本机验过（pywebview 未安装，`requirements-desktop.txt` 是可选依赖），
验的是 `--serve` 的服务形态；spec 里 `console=True`（要"没有黑框"就改 `console=False`）。

## 13. 插件管理面（阶段 N：模型能看清、用户能动手）

到阶段 M 为止，"谁能改插件"只有两条路：写文件（agent 或部署者）+ 批准卡。模型那边还缺一环——
**它看不到自己有哪些插件**：`inspect_graph` 只给"图里参与的片段"与"可用服务"，而只加工具
（`ctx.tools.register`）或只挂资产（`ctx.assets.mount`）的插件**不贡献片段**，在图里完全不可见
（真跑里 `word_count`、`panel_frontend` 就是这样消失的）。用户那边也缺一环：只能靠手工改文件与信任清单。

### 13.1 给模型：一份清单（`plugins`）

`inspect_graph` 的 payload 多一块 `plugins`：**内置 + 全局库 + 当前工作区库**，每行
`name / source / file / state / reason`：

- `source`：`内置`（装配的一部分）/ `全局` / `工作区`；
- `state`：`ACTIVE` / `PENDING`（`reason` 点名缺哪个服务）/ `FAILED`（`reason` 是原文）/
  `待批准`（工作区库还没批准）/ `已停用`（文件名 `_` 前缀）；
- 数据来自已有的两个真相（`_loaded`：文件 → fiber，状态直接问 fiber；`last_report`：装载/待批准/失败），
  **不另扫一遍盘**，所以不会跟实际状态对不上；
- `install_plugin` / `add_fragment` 的返回里附一句"当前插件 N 个（生效 M）/ 需要留意：…"——
  写完就知道自己在整体里处于什么位置。

### 13.2 给用户：一个管理面（不造第二套生命周期）

**三层归属，一条铁律（不维护第二份状态）**：

| 层 | 拥有 | 不碰 |
| --- | --- | --- |
| 内核（fiber / registry） | 装载、卸载、重启、状态 | 文件、信任 |
| 插件库（`discover.py`） | 文件→fiber 映射、信任清单、作用域、轮询 | HTTP、界面 |
| 管理面（`web/service/plugin_admin.py` + `web/api/plugins.py`） | 把上面两层**翻译成用户动作**，做完返回新清单 | 生命周期、第二份状态 |

**状态机（写死"停用只有一种"）**：`待批准` —启用→ `ACTIVE` —停用→ `已停用` —启用→ `ACTIVE`；
`FAILED` / `PENDING` 用**重读**或补服务解决。不发明第三种状态——否则"停用"与"撤信任"会分叉，
最后没人说得清哪个算数。

**动作 → 原语（一个动作一个原语，没有新机制）**：

| 动作 | 落到哪个原语 |
| --- | --- |
| 启用 / 停用 | `trust` / `untrust`（工作区库）+ 文件名加/去 `_` 前缀（两级通用） |
| 重读 | `PluginDiscovery.reload_file`（卸下再扫，不新增生命周期） |
| 删除 | 撤信任 + `unlink` + 立刻扫（危险动作，界面负责二次确认） |
| 列清单 | `PluginLibraries.inventory`（**与 `inspect_graph` 给模型的是同一份**） |

**两条边界**：
- **内置插件不在管理范围**：它们是装配的一部分（缺了启动就失败）。清单里列出来（`source: 内置`）、
  但没有动作；要改组合 = 改装配清单。触发条件 = 出现"用户想在界面上选装内置插件"的真实需求。
- **管理面不绕过回合边界**：结构类改动仍在下一个回合生效——agent 改的和用户点的**同一套规则**；
  能力类（工具/资产）本来就是装载即生效。

**接口**：`GET /plugins`（清单 + 两级库目录）、`POST /plugins/enable|reload|remove`。
服务层**只收文件名**（拒路径、拒子目录），越界在那里就被拒（`InvalidInput`），不靠界面自觉；
每个动作做完都**立刻扫一次**（改名/删除发生在扫描之后，不扫就会残留旧状态——"文件都删了
还显示待批准"，这条是被用例抓出来的）。

**管理面板（已落地，由 agent 自己在基准任务里做完）**：顶部「插件」按钮开面板——清单逐行渲染
（名字/来源/状态/原因）、按状态给动作（启用或停用、重读、删除带二次确认）、动作后用返回的新清单
原地刷新、两级库路径显示在表头。现场用浏览器逐条点过：打开面板 → 行出现 → 点「启用」→ 磁盘上的
信任清单真的被写进去。

这一轮（基准任务 + 浏览器复核）又翻出三个真问题，都已修：

1. **打开面板只看得到内置行**：工作区库是"按会话工作区按需登记"的，没登记就看不见它的文件，
   面板会假装"这里什么都没有" → `overview` 先 `ensure` 那个工作区（登记是这一层的责任）；
2. **`InvalidInput` 走通用 500 出口**：`{"file":"nope.py"}` 这种手滑会打一整段 traceback +
   uvicorn 的 "Exception in ASGI application"，把真故障淹了 → 加 `invalid_input` 处理器
   （400 + 一行 INFO，`browse` / `skills` 同样受益）；
3. **动作消息会说谎**：批准一个"待批准"的文件时，`changed` 只跟踪改名、没算上"新写入信任"，
   于是回了"本来就是这个状态，没改动" → 信任写入也计入改动。

### 13.3 阶段 O：原子化工具（把"往返次数"当作一等性能指标）

一次真跑暴露的问题不是"模型笨"，而是**接口粒度**：让 agent 自己改那份 2400 行的前端单文件，
它花了 **65 次工具调用 ≈ 65 次模型往返、31.6 分钟，其中 91% 的时间在往返之间**
（`read` 34 次、`edit` 16 次，大半是"改一处、再看一眼"）。同一个任务交给一次输出能带多个动作的
执行体（人、上层 agent）只要个位数往返——差的是编排粒度，不是智力。

于是 `builtin/atomic_tools` 补两个**批量版**（工具调用是一轮一次往返，批量版把 N 次压成 1 次）：

| 工具 | 语义 |
| --- | --- |
| `edit_many(edits)` | 一次改多处（可跨文件）；**失败即停**并说清"第几条、为什么、前面几条已应用"——批量最怕默默改一半；单文件时照样给界面画差异 |
| `read_many(reads)` | 一次读多段/多文件；单条失败不影响其它（读是幂等的），每段仍带行号与续读位置 |

配套改动（都是"让批量/顶替成立"的必要条件，不是顺手）：

- **`grep` 支持 `before`/`after` 上下文**（内置工具加参数；`:` 命中行、`-` 上下文）——
  "这行在什么函数里"常常比这行本身重要，省掉一次"再 read 一遍整个文件"；
- **`edit` / `read` 的本体抽成可复用函数**（`apply_edit` / `read_text` / `grep_text`）：
  插件做的是**组合**，不是复制一遍换行风格与宽松匹配的逻辑；
- **`Toolbox.register` 的同名顶替改为可回退**：卸载插件时还原被顶替的那个工具。
  "注册即 effect"承诺的是**回到注册前**，原来的实现是"删掉这个名字"——插件想升级一个内置工具
  （同名注册、行为是超集），一卸载那个功能就凭空消失。这条有专门用例。

**约定写着工具描述里**（模型看得到的地方）：`edit`/`read` 的说明里明确"要改多处用 `edit_many`、
要读好几处用 `read_many`，别一处一次"——接口粒度要配上使用指引，否则模型仍然一处一调。

**速度记账（同 agent、同模型）**：

| | 基线（无批量工具） | 补了批量工具之后 |
| --- | --- | --- |
| 任务 | 读 2400 行前端 + 找并改 7 处 | 给前端加插件管理面板（更大） |
| 工具调用总数 | 65 次（read 34 / **edit 16** / grep 10 / bash 5） | 48 次（bash 22 / read 20 / **edit_many 4** / edit 2） |
| 编辑类调用 | 16 次，一处一次 | **6 次**（4 次 edit_many 各带多条） |
| 调用密度 | 2 次/分钟（65 次用了 31.6 分钟） | **7.5 次/分钟**（48 次用了 6.4 分钟，同尺度的活还没做完就被停） |
| 时间去向 | ≥10 秒的空档占 91% | 空档明显缩短（批量调用之间不再有"想一处、写一处"的串行） |

结论：**接口粒度确实是主因之一**——它自己选了 `edit_many`（4 次调用带走全部改动），
编辑类往返从"一处一次"降到"一次多条"；把活干完的剩余时间主要还压在网关的单次延迟上。
（这条基准是**跑到 6.4 分钟主动停的**，不是完成值：UI 那半成品已回退。脚本在
`scratchpad/bench_panel.py`，想跑完随时可以重跑。）

工具只是"少往返"的一半，另一半在**任务怎么交**：一次只给一个问题、把定位好的行号喂进去、
改完不必重读。这三条以后写任务时照用。
