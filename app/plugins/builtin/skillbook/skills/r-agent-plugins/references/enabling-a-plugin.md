# 启用、验证与回退

## 放哪

| 库 | 路径 | 信任 |
| --- | --- | --- |
| 全局库 | `PLUGINS_DIR`（默认 `~/.my_agent/plugins`） | **装载即信任**（你自己的目录） |
| 工作区库 | `<会话的工作区>/.my_agent/plugins/` | **按文件批准**：文件名要出现在该工作区 `.my_agent/plugins.json` 的 `trusted` 里 |

工作区库默认关（`PLUGINS_WORKSPACE=0`）；打开后**作用域 = 会话工作区**——
A 工作区批准的插件只进 A 的会话，各自一套片段、版本与信任清单。

```json
// <工作区>/.my_agent/plugins.json
{"trusted": ["research.json", "notes.py"]}
```

这份清单在沙箱里是**硬阻断区**：读写都拒、永不提示（写它 = 自己批准自己的插件）。
只有人能改它，或让 `add_fragment` 走完审批后由服务端代写。

## 生效时机

- **装载是即时的**（文件一变，轮询发现后立刻装载/卸载）；
- **换图在回合边界**：正在跑的那一轮用旧图，下一轮开始用新图；
- **改实现不触发换图**：只提供服务（不贡献片段）的 `.py` 被改后只重载模块——片段集合没变就
  **没有新图**，已合成进图的节点仍跑合成那一刻的旧实现（注册表里已是新服务，静默分叉）。
  让新实现上车：先动片段集合（如改一下引用它的 `.json`），再过回合边界；
- **批准**（写进 `trusted`）会立刻触发装载，但生效同样在边界；
- **合成失败不改运行图**：报告里点名失败原因，其余片段照常。

## 验证清单

1. **启动日志**："插件库：… 装载 N / 待批准 M / 失败：谁（为什么）"；
2. **合成报告**（每次换图打一次）：版本、结构哈希、参与片段、每个锚点的挂载链、待批准、
   `未参与`（PENDING 的插件缺哪个服务）、警告；
3. **`inspect_graph`**（模型可调）：报告 + 运行中版本的片段清单 + 最近几次审计；
4. **审计表 `graph_version`**：一行一次换图（`reason` = 启动 / 结构变化 / 熔断），含 mermaid 存档；
5. **`python -m app.harness`**：把当前骨架导出成 mermaid（空锚点也会画出来）。

## 一个可用的小闭环

```
写文件 → 放进插件库 → （工作区库还要）加进 trusted → 看日志"已装载"
  → 下一个回合边界 → 看报告/审计确认链挂上了 → 需要时删文件回退
```

模型自己动手时走 `add_fragment`（`.json`）/ `install_plugin`（`.py`，要装配时放行）：
写文件 → 弹确认卡 → 人点"确认" → 服务端写 trusted → 下一个回合边界生效。拒绝则文件留在
"待批准"名单里，删掉它就是撤销。

## 回退与排障

| 现象 | 查什么 |
| --- | --- |
| 文件在但没生效 | 是"待批准"吗？（报告/日志点名）；到回合边界了吗？ |
| 改了实现但节点还跑旧代码 | 只改提供方 `.py` 不触发重合成（实现冻结在合成那一刻）——动一下引用它的 `.json`，再过回合边界 |
| 报 `INTERFACE_MISSING` | 片段里的 `interface` 还没有服务提供（先装提供方，或换名字） |
| 报 `ANCHOR_UNKNOWN` | 锚点写错（用 `inspect_graph` 看骨架锚点表） |
| 报 `FRAGMENT_DUPLICATE` | 同作用域里 `id` 重复 |
| 报告里"未参与（缺少服务 X）" | 插件 PENDING：它的 `inject` 里哪个服务还没到 |
| 节点连炸三次 | 被熔断自动摘出（报告里 `停用` 名单）；修好文件即重新装载 |
| 读技能/资料弹授权卡 | 那个目录不在受信只读根里（`builtin/sandbox` 的 `trusted_read_roots`，或让插件 `sandbox.trust(dir)`） |

**怎么退**：删插件文件 = 撤销声明，回合边界回到原样；撤信任 = 把名字从 `trusted` 去掉。
两者都不需要重启进程（热重载轮询会发现；急的话看日志确认它已卸载）。
